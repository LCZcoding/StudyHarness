## 1. 本次范围（保留什么、砍什么）

**保留（你要求的最小可用）**

| 能力 | 最小可用形态 |
| --- | --- |
| 工具调用 | `POST /ai/agent/stream` 走 `LoveApp` 已有的 `allTools`（`WebSearchTool` 等），流式返回并落库 |
| RAG | 自由问答加一个 `useRag` 开关，按 `userId` 过滤检索**你自己的**资料 |
| 资料接入 | 两种输入：**粘贴文本** + **上传 `.md` / `.txt`**（用户自己下载整理，质量可控） |
| 主动回忆测试 | 出题 → 作答 → AI 只挑漏洞 → 记成绩 |
| 简化调度 | 1 / 3 / 7 天三档，`UNIQUE` 约束保证幂等 |
| 交错练习 | 复习时混入另一条资料的 1 道新题 |

**砍（明确不做）**

- 关联提问（"这两者什么关系？"）→ 多一次 LLM 调用 + 一套提示词，收益低
- **网页自动抓取**（搜索 → 抓正文 → 清洗 → 切片 → 入库）→ 需要处理 SPA 抓不到、站点结构各异、外网失败三类问题，
  且文档质量交给自动清洗后不可控。改为「用户自己下载 → 上传/粘贴」，同一条链路的**输入侧**由人把关
- 练习模式 `PRACTICE` 的真实使用（枚举值留着，不在本轮前端暴露）
- 知识图谱可视化（C 类，永久不做）

**总表数：6 张**（已有 3 张 + 新增 3 张）

## 2. 阶段 0：建表

### 2.1 追加到 `db/schema.sql` 末尾

```sql
-- ============================================================
-- 表设计 v2（MVP 主干）：知识条目 / 测试成绩 / 复习排期
-- 执行顺序：t_knowledge_item -> t_test_record -> t_review_schedule
-- ============================================================

-- 用户自己的学习材料。第一层接入只有"标题 + 正文"，不做切片。
CREATE TABLE IF NOT EXISTS t_knowledge_item (
    id         UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id    UUID         NOT NULL REFERENCES t_user(id),
    title      VARCHAR(100) NOT NULL,
    source_url VARCHAR(500),                        -- 可选：记录来源（文件名 / URL），粘贴可留空
    content    TEXT         NOT NULL,
    created_at TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_knowledge_item_user ON t_knowledge_item(user_id);

-- 会话与"取材资料"绑定：作答时要靠它确定成绩归到哪条资料。
-- 不能在 t_test_record 里反查：第一次作答时成绩还没写，会查到 null。
ALTER TABLE t_conversation
    ADD COLUMN IF NOT EXISTS knowledge_item_id UUID REFERENCES t_knowledge_item(id);

-- 一次作答 = 一条成绩。question_message_id 指向 t_message 里那条 QUESTION。
CREATE TABLE IF NOT EXISTS t_test_record (
    id                  BIGINT       PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    user_id             UUID         NOT NULL REFERENCES t_user(id),
    knowledge_item_id   UUID         NOT NULL REFERENCES t_knowledge_item(id),
    question_message_id BIGINT       NOT NULL REFERENCES t_message(id),
    answer              TEXT         NOT NULL,
    feedback            TEXT         NOT NULL,
    verdict             VARCHAR(10)  NOT NULL CHECK (verdict IN ('PASS','PARTIAL','FAIL')),
    attempt_no          INT          NOT NULL DEFAULT 1,
    asked_for_help      BOOLEAN      NOT NULL DEFAULT false,
    created_at          TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_test_record_item ON t_test_record(knowledge_item_id);

-- 复习排期。stage 取 1 / 3 / 7（天）。
-- UNIQUE (test_record_id, stage) 是幂等的实现：重复排期时 ON CONFLICT DO NOTHING，
-- 而不是靠"先查再插"——先查再插在并发下会漏。
CREATE TABLE IF NOT EXISTS t_review_schedule (
    id             UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id        UUID         NOT NULL REFERENCES t_user(id),
    test_record_id BIGINT       NOT NULL REFERENCES t_test_record(id),
    stage          INT          NOT NULL CHECK (stage IN (1,3,7)),
    due_at         TIMESTAMPTZ  NOT NULL,
    status         VARCHAR(10)  NOT NULL DEFAULT 'PENDING'
                                CHECK (status IN ('PENDING','DONE','CANCELED')),
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    done_at        TIMESTAMPTZ,
    CONSTRAINT uq_review_record_stage UNIQUE (test_record_id, stage)
);

-- 到点扫描的索引：只关心 PENDING，所以用部分索引
CREATE INDEX IF NOT EXISTS idx_review_due
    ON t_review_schedule(user_id, due_at) WHERE status = 'PENDING';
```

### 2.2 为什么这么设计（面试会被问的三处）

| 设计 | 理由 |
| --- | --- |
| 题目不单独建表，存进 `t_message`（`role=ASSISTANT, type=QUESTION`） | 题目本来就是对话的一部分，复用已有枚举与历史接口；`t_test_record` 只需外键指回那条消息 |
| 成绩表存 `attempt_no` 与 `asked_for_help` | 「第几次答对」「是否求助过」正是"回忆表现"的度量口径，也是「求助过就优先重问」的依据 |
| 幂等靠 `UNIQUE` + `ON CONFLICT DO NOTHING` | 定时任务/重试都可能重复排期；唯一约束是数据库层的事实，比应用层判重可靠 |

## 3. 阶段 1：资料接入（第一层）

### 3.1 契约

| 方法 | 路径 | 请求 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| POST | `/knowledge-items` | `{"title":"...", "content":"..."}` | `201` + `Location` + `{"knowledgeItemId":"<uuid>"}` | 401 未登录 / 400 字段为空或超长 |
| POST | `/knowledge-items/upload` | `multipart/form-data`：`file` + `title` | `201` + `{"knowledgeItemId":"<uuid>"}` | 401 / 400 |
| GET | `/knowledge-items` | — | `200 [{"knowledgeItemId","title","sourceUrl","createdAt"}]` | 401 |

`content` 上限 20000 字符（**粘贴接口的 `@Size`**）：粘贴一篇笔记够用，也避免把整篇文章塞进 prompt 把上下文撑爆。
**上传接口另算**：文件上限 100KB（约 3 万汉字）。两者独立——上传由 `multipart` 限制，不走 `@Size`。

**上传只支持 `.md` / `.txt`**，即纯文本与 Markdown。理由：PDF/Word 要额外解析库（`PDFBox`/`POI`），
解析出的排版噪声反而拉低出题质量；用户下载文档后另存为 `.md` 或直接复制粘贴，成本低且完全可控。

`application.yml` 加一段（Spring 默认 1MB，这里收紧到 100KB，超限会直接拒绝请求）：

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 100KB
      max-request-size: 100KB
```

```java
package com.lcz.aiagentstudy.repository;

import com.lcz.aiagentstudy.model.KnowledgeItemRow;
import lombok.RequiredArgsConstructor;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Repository;

import java.time.OffsetDateTime;
import java.util.List;
import java.util.Optional;
import java.util.UUID;

@Repository
@RequiredArgsConstructor
public class KnowledgeItemRepository {
    private final JdbcTemplate jdbcTemplate;

    public UUID create(UUID userId, String title, String sourceUrl, String content) {
        return jdbcTemplate.queryForObject(
                "insert into t_knowledge_item (user_id, title, source_url, content) values (?, ?, ?, ?) returning id",
                UUID.class, userId, title, sourceUrl, content);
    }

    // 列表不取 content：正文可能很长，列表只需要标题
    public List<KnowledgeItemRow> findAllByUserId(UUID userId) {
        return jdbcTemplate.query("""
                        select id, title, source_url, created_at
                          from t_knowledge_item
                         where user_id = ?
                         order by created_at desc
                        """,
                (rs, rowNum) -> new KnowledgeItemRow(
                        rs.getObject("id", UUID.class),
                        rs.getString("title"),
                        rs.getString("source_url"),
                        null,
                        rs.getObject("created_at", OffsetDateTime.class)),
                userId);
    }

    public Optional<KnowledgeItemRow> findById(UUID id) {
        List<KnowledgeItemRow> rows = jdbcTemplate.query("""
                        select id, title, source_url, content, created_at
                          from t_knowledge_item
                         where id = ?
                        """,
                (rs, rowNum) -> new KnowledgeItemRow(
                        rs.getObject("id", UUID.class),
                        rs.getString("title"),
                        rs.getString("source_url"),
                        rs.getString("content"),
                        rs.getObject("created_at", OffsetDateTime.class)),
                id);
        return rows.stream().findFirst();
    }

    // 归属校验用：只回答"是不是这个人的"，不泄露条目是否存在
    public boolean belongsTo(UUID itemId, UUID userId) {
        return Boolean.TRUE.equals(jdbcTemplate.queryForObject(
                "select exists(select 1 from t_knowledge_item where id = ? and user_id = ?)",
                Boolean.class, itemId, userId));
    }
}
```

### 3.4 `service/KnowledgeService.java`

```java
package com.lcz.aiagentstudy.service;

import com.lcz.aiagentstudy.exception.ForbiddenException;
import com.lcz.aiagentstudy.model.KnowledgeItemRow;
import com.lcz.aiagentstudy.repository.KnowledgeItemRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.beans.factory.ObjectProvider;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.Map;
import java.util.UUID;

@Service
@RequiredArgsConstructor
@Slf4j
public class KnowledgeService {
    private final KnowledgeItemRepository knowledgeItemRepository;

    // 用 ObjectProvider：pgvector 未启用（app.pgvector.enabled=false）时容器里没有 VectorStore，
    // 直接注入会启动失败。向量是增强项，不该成为"存资料"的前置条件。
    private final ObjectProvider<VectorStore> vectorStoreProvider;

    public UUID create(UUID userId, String title, String sourceUrl, String content) {
        UUID id = knowledgeItemRepository.create(userId, title, sourceUrl, content);
        indexQuietly(id, userId, title, content);
        return id;
    }

    public List<KnowledgeItemRow> list(UUID userId) {
        return knowledgeItemRepository.findAllByUserId(userId);
    }

    /** 出题/复习用：先验归属，再取正文。两种情况同一句文案，不泄露"存在与否"。 */
    public KnowledgeItemRow requireOwned(UUID itemId, UUID userId) {
        if (!knowledgeItemRepository.belongsTo(itemId, userId)) {
            throw new ForbiddenException("资料不存在或无权访问");
        }
        return knowledgeItemRepository.findById(itemId)
                .orElseThrow(() -> new ForbiddenException("资料不存在或无权访问"));
    }

    /**
     * 向量化。文档 id 直接用 knowledgeItemId —— 这样"一条资料"与"一条向量"一一对应，
     * 将来要删/要更新，凭同一个 id 就能定位，不用再存一份映射。
     * 入库失败只记日志：文本已经落库，出题可以退化为直接读正文，不该因为向量库抖动就 500。
     */
    private void indexQuietly(UUID itemId, UUID userId, String title, String content) {
        VectorStore vectorStore = vectorStoreProvider.getIfAvailable();
        if (vectorStore == null) {
            log.warn("VectorStore 未启用，跳过向量化: knowledgeItemId={}", itemId);
            return;
        }
        try {
            vectorStore.add(List.of(new Document(
                    itemId.toString(),
                    content,
                    Map.of("userId", userId.toString(), "title", title))));
        } catch (Exception e) {
            log.warn("向量化失败，资料已保存但暂不参与 RAG: knowledgeItemId={}, cause={}",
                    itemId, e.getMessage());
        }
    }
}
```

### 4.3 `service/QuizStore.java`（所有写操作集中在这里）

```java
package com.lcz.aiagentstudy.service;

import com.lcz.aiagentstudy.model.ConversationMode;
import com.lcz.aiagentstudy.model.MessageRole;
import com.lcz.aiagentstudy.model.MessageType;
import com.lcz.aiagentstudy.repository.ConversationRepository;
import com.lcz.aiagentstudy.repository.MessageRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.ArrayList;
import java.util.List;
import java.util.UUID;

/**
 * 主干的写入口。单独一个 bean 的原因与④格相同：
 * 出题要先调模型（慢、会失败），再写库；把 @Transactional 和被调用的方法放同一个类里，
 * 自调用绕过 Spring 代理，注解会静默失效。
 */
@Service
@RequiredArgsConstructor
public class QuizStore {
    private final ConversationRepository conversationRepository;
    private final MessageRepository messageRepository;

    @Transactional
    public UUID createSelfTestConversation(UUID userId) {
        return conversationRepository.create(userId, ConversationMode.SELF_TEST.name());
    }

    /** 一个事务写 3 道题，返回它们的消息 id（顺序与入参一致）。 */
    @Transactional
    public List<Long> appendQuestions(UUID conversationId, List<String> questions) {
        List<Long> ids = new ArrayList<>(questions.size());
        for (String q : questions) {
            ids.add(messageRepository.insertReturningId(
                    conversationId, MessageRole.ASSISTANT.name(), MessageType.QUESTION.name(), q));
        }
        conversationRepository.touch(conversationId);
        return ids;
    }
}
```

### 4.4 `service/QuizService.java`

```java
package com.lcz.aiagentstudy.service;

import com.lcz.aiagentstudy.model.KnowledgeItemRow;
import lombok.RequiredArgsConstructor;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.UUID;

@Service
@RequiredArgsConstructor
public class QuizService {
    private static final String SYSTEM_PROMPT = """
            你是出题官，只出题、不答题。
            规则：
            1. 必须严格基于用户给出的材料出题，不得引入材料以外的知识点。
            2. 只输出问题，绝不包含答案、提示、解释、编号说明。
            3. 问题要能靠"回忆"作答（是什么 / 为什么 / 怎么做），不要出选择题。
            4. 每题一句话，20 到 60 字。
            """;

    private final ChatModel chatModel;
    private final KnowledgeService knowledgeService;
    private final QuizStore quizStore;

    public record QuizResult(UUID conversationId, List<Long> questionIds, List<String> questions) {
    }

    // 不标 @Transactional：这里要等模型，不能占着连接
    public QuizResult generate(UUID userId, UUID knowledgeItemId) {
        KnowledgeItemRow item = knowledgeService.requireOwned(knowledgeItemId, userId);
        List<String> questions = draft(item.content());
        if (questions.size() != 3) {
            throw new IllegalStateException("模型未按要求返回 3 道题，请重试");
        }

        UUID conversationId = quizStore.createSelfTestConversation(userId, knowledgeItemId);
        List<Long> ids = quizStore.appendQuestions(conversationId, questions);
        return new QuizResult(conversationId, ids, questions);
    }

    /** 复习的交错题：只出 1 道。出不来就返回 empty，不阻断这次复习。 */
    public java.util.Optional<String> generateOne(KnowledgeItemRow item) {
        try {
            return draft(item.content()).stream().findFirst();
        } catch (RuntimeException e) {
            return java.util.Optional.empty();
        }
    }

    /** 只要求"至少 1 道"：出 3 道还是 1 道由调用方决定，这里不做口径判断。 */
    private List<String> draft(String content) {
        ChatClient client = ChatClient.builder(chatModel).defaultSystem(SYSTEM_PROMPT).build();
        QuizDraft draft = client.prompt()
                .user("材料如下：\n\n" + content + "\n\n请出 3 道题。")
                .call()
                .entity(QuizDraft.class);
        if (draft == null || draft.questions() == null || draft.questions().isEmpty()) {
            throw new IllegalStateException("模型未返回题目，请重试");
        }
        return draft.questions();
    }

    /** 结构化输出用的形状：只有题目，从结构上就不给答案留位置。 */
    public record QuizDraft(List<String> questions) {
    }
}
```

> 关于 `entity()`：Spring AI 会要求模型按 JSON 返回并反序列化。**它可能失败**（模型返回多余文字）。
> 失败时抛 `IllegalStateException` → 500，前端提示重试。这是本轮有意接受的粗糙：先跑通，再谈重试与兜底解析。

```java
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.stereotype.Service;

import java.util.UUID;

@Service
@RequiredArgsConstructor
public class AnswerService {
    private static final String SYSTEM_PROMPT = """
            你是严格的批改官，只挑漏洞，不给答案。
            规则：
            1. 绝不直接给出正确答案；最多指出"你漏了哪一点""这个说法不对，去想想为什么"。
            2. 先判断用户是否真的答到了关键点，再给结论：
               - PASS：关键点全部答到
               - PARTIAL：答到一部分，或表述模糊
               - FAIL：答错、答非所问、或明显没复习
            3. feedback 控制在 120 字以内，必须包含一个"下一步该回看什么"的指引。
            4. 用户如果求助过（askedForHelp=true），反馈里点明"这次是问过才答出来的"，但不要羞辱用户。
            """;

    private final ChatModel chatModel;
    private final AnswerStore answerStore;

    public record SubmitResult(Verdict verdict, String feedback) {
    }

    // 不标 @Transactional：判分要等模型
    public SubmitResult submit(UUID userId, long questionMessageId, String answer, boolean askedForHelp) {
        QuestionLookup.Question question = answerStore.requireOwnedQuestion(questionMessageId, userId);
        if (question == null) {
            throw new ForbiddenException("题目不存在或无权访问");
        }

        VerdictResult result = grade(question.text(), answer, askedForHelp);
        Verdict verdict = Verdict.valueOf(result.verdict());

        answerStore.saveAnswerRound(question, userId, answer, result.feedback(), verdict, askedForHelp);
        return new SubmitResult(verdict, result.feedback());
    }

    private VerdictResult grade(String question, String answer, boolean askedForHelp) {
        ChatClient client = ChatClient.builder(chatModel).defaultSystem(SYSTEM_PROMPT).build();
        VerdictResult r = client.prompt()
                .user("题目：" + question + "\n\n用户作答：" + answer + "\n\naskedForHelp=" + askedForHelp)
                .call()
                .entity(VerdictResult.class);
        if (r == null || r.verdict() == null || r.feedback() == null) {
            throw new IllegalStateException("模型未返回合法的批改结果，请重试");
        }
        return r;
    }
}
```

```java
package com.lcz.aiagentstudy.service;

import com.lcz.aiagentstudy.model.MessageRole;
import com.lcz.aiagentstudy.model.MessageType;
import com.lcz.aiagentstudy.model.Verdict;
import com.lcz.aiagentstudy.repository.*;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.UUID;

@Service
@RequiredArgsConstructor
public class AnswerStore {
    private static final int[] STAGES = {1, 3, 7};

    private final QuestionRepository questionRepository;
    private final MessageRepository messageRepository;
    private final TestRecordRepository testRecordRepository;
    private final ReviewScheduleRepository reviewScheduleRepository;
    private final ConversationRepository conversationRepository;

    /** 反查题目并校验归属；不是这个人的题，与"不存在"同一出口。 */
    public QuestionLookup.Question requireOwnedQuestion(long questionMessageId, UUID userId) {
        return questionRepository.findWithOwner(questionMessageId).stream()
                .filter(q -> q.userId().equals(userId))
                .findFirst()
                .map(q -> new QuestionLookup.Question(
                        q.questionId(), q.text(), q.conversationId(), q.knowledgeItemId()))
                .orElse(null);
    }

    /**
     * 一个事务写完这一轮：两条消息 + 一条成绩 + 三条排期。
     * 顺序刻意是"先成绩后排期"：排期外键指向成绩，反过来插不进去。
     */
    @Transactional
    public void saveAnswerRound(QuestionLookup.Question question, UUID userId,
                                String answer, String feedback, Verdict verdict, boolean askedForHelp) {
        UUID conversationId = question.conversationId();

        messageRepository.insert(conversationId, MessageRole.USER.name(), MessageType.ANSWER.name(), answer);
        messageRepository.insert(conversationId, MessageRole.ASSISTANT.name(), MessageType.FEEDBACK.name(), feedback);

        int attemptNo = testRecordRepository.countByQuestion(question.questionId()) + 1;
        long recordId = testRecordRepository.insert(userId, question.knowledgeItemId(), question.questionId(),
                answer, feedback, verdict.name(), attemptNo, askedForHelp);

        for (int stage : STAGES) {
            reviewScheduleRepository.insertIgnore(userId, recordId, stage);
        }

        conversationRepository.touch(conversationId);
    }
}
```

## 6. 阶段 4：到点复习（含交错）

### 6.1 契约

| 方法 | 路径 | 请求 | 成功 |
| --- | --- | --- | --- |
| GET | `/review/pending` | — | `200 {"count":2,"items":[{"scheduleId":"...","dueAt":"...","stage":1,"question":"..."}]}` |
| POST | `/review/start` | — | `200 {"conversationId":"...","questions":[{"questionId":9,"text":"..."}]}` |

规则（最小实现）：

1. 取**到期未做**的排期，最多 **3 条**，按 `due_at` 升序。
2. 一条排期 = 把**原来那道题**重问一次（不重新生成，省一次模型调用，也保证"复习的是同一考点"）。
3. **交错**：再额外从该用户**另一条资料**出 **1 道新题**，混在同一次复习里。凑不到另一条资料就跳过（不报错）。
4. `start` 会把参与的排期标 `DONE`，写 `done_at`。
5. 没有到期项 → `200 {"conversationId":null,"questions":[]}`，不建空会话。

### 6.5 `service/ReviewService.java`

```java
package com.lcz.aiagentstudy.service;

import com.lcz.aiagentstudy.model.ReviewItemRow;
import com.lcz.aiagentstudy.repository.ReviewScheduleRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;
import java.util.UUID;

@Service
@RequiredArgsConstructor
public class ReviewService {
    private static final int MAX_DUE = 3;

    private final ReviewScheduleRepository reviewScheduleRepository;
    private final KnowledgeService knowledgeService;
    private final QuizService quizService;
    private final QuizStore quizStore;

    public List<ReviewItemRow> pending(UUID userId) {
        return reviewScheduleRepository.findDue(userId, MAX_DUE);
    }

    public record ReviewStart(UUID conversationId, List<Long> questionIds,
                              List<String> questions, List<UUID> scheduleIds) {
    }

    public ReviewStart start(UUID userId) {
        List<ReviewItemRow> due = pending(userId);
        if (due.isEmpty()) {
            return new ReviewStart(null, List.of(), List.of(), List.of());
        }

        // 1) 先把题目凑齐，再建会话：模型调用失败时不会留下一条空会话
        List<String> questions = new ArrayList<>();
        for (ReviewItemRow item : due) {
            questions.add(item.question());          // 原题重问，不重新生成
        }

        // 2) 交错：从"没有被这些到期题覆盖"的资料里现出 1 道新题
        List<UUID> exclude = due.stream().map(ReviewItemRow::knowledgeItemId).toList();
        reviewScheduleRepository.findAnotherKnowledgeItem(userId, exclude)
                .map(itemId -> knowledgeService.requireOwned(itemId, userId))
                .flatMap(quizService::generateOne)
                .ifPresent(questions::add);

        UUID conversationId = quizStore.createReviewConversation(userId);
        List<Long> ids = quizStore.appendQuestions(conversationId, questions);
        List<UUID> scheduleIds = due.stream().map(ReviewItemRow::scheduleId).toList();
        quizStore.markDone(scheduleIds);

        return new ReviewStart(conversationId, ids, questions, scheduleIds);
    }
}
```

**方法一：RAG 流式问答**

```java
    public Flux<String> doChatByStreamWithRag(String message, String chatId, String userId) {
        String context = retrieve(message, userId);
        String userMessage = context.isBlank()
                ? message
                : "请只依据以下资料回答；资料里没有的就说不知道。\n\n===资料开始===\n"
                  + context + "\n===资料结束===\n\n问题：" + message;

        return chatClient.prompt()
                .user(userMessage)
                .advisors(spec -> spec.param(ChatMemory.CONVERSATION_ID, chatId))
                .stream()
                .content();
    }

    /** 按 userId 过滤：只检索这个用户自己的资料，绝不跨用户。 */
    private String retrieve(String message, String userId) {
        if (loveAppVectorStore == null) {
            return "";
        }
        SearchRequest request = SearchRequest.builder()
                .query(message)
                .topK(4)
                .filterExpression("userId == '" + userId + "'")
                .build();
        return loveAppVectorStore.similaritySearch(request).stream()
                .map(Document::getText)
                .collect(java.util.stream.Collectors.joining("\n---\n"));
    }
```

### 7.3 `ChatService` 改造

```java
    // 三个入口共用"累积全文 + 完成时落库"，只是底层流不同
    public Flux<String> stream(UUID conversationId, String message, boolean useRag, UUID userId) {
        StringBuilder full = new StringBuilder();
        Flux<String> source = useRag
                ? loveApp.doChatByStreamWithRag(message, conversationId.toString(), userId.toString())
                : loveApp.doChatByStream(message, conversationId.toString());

        return source
                .publishOn(reactor.core.scheduler.Schedulers.boundedElastic())  // ④格踩坑：JDBC 不能跑在数据源线程
                .doOnNext(full::append)
                .doOnComplete(() -> messageService.appendRound(conversationId, message, full.toString()));
    }

    public Flux<String> streamWithTools(UUID conversationId, String message) {
        StringBuilder full = new StringBuilder();
        return loveApp.doChatByStreamWithTools(message, conversationId.toString())
                .publishOn(reactor.core.scheduler.Schedulers.boundedElastic())
                .doOnNext(full::append)
                .doOnComplete(() -> messageService.appendRound(conversationId, message, full.toString()));
    }
```

`AiChatController` 的 `StreamRequest` 加字段：

```java
            boolean useRag
```

调用处改为 `chatService.stream(conversationId, req.message(), req.useRag(), userId)`。

> **`publishOn` 的位置很关键**：放在 `doOnNext` 之前，整条下游（含 `doOnComplete` 里的 JDBC）都会被切到
> `boundedElastic`；放在之后，只有回调被切，`onNext` 仍在原线程。这就是④格那条踩坑的正解。
>
> **改签名会让现有测试编译不过**：`ChatServiceTest` 里原来调的是 `stream(conversationId, message)`，
> 现在多两个参数，改成 `stream(conversationId, message, false, userId)` 即可。
> 这类"改实现顺带改调用方"的编译错误**是好事**——它替你找全了所有调用点。

```java
package com.lcz.aiagentstudy.controller;

import com.lcz.aiagentstudy.service.ChatService;
import com.lcz.aiagentstudy.service.ConversationService;
import com.lcz.aiagentstudy.web.CurrentUserResolver;

import jakarta.validation.Valid;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Size;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.servlet.mvc.method.annotation.SseEmitter;
import reactor.core.Disposable;

import java.io.IOException;
import java.util.UUID;

/** 带工具的对话入口。骨架与 /ai/chat/stream 一致：身份(401) → 归属(403) → 开流。 */
@RestController
@RequestMapping("/ai")
@RequiredArgsConstructor
public class AgentChatController {
    private final CurrentUserResolver currentUserResolver;
    private final ConversationService conversationService;
    private final ChatService chatService;

    public record AgentRequest(
            @NotNull(message = "conversationId 不能为空") UUID conversationId,
            @NotBlank(message = "message 不能为空")
            @Size(max = 4000, message = "message 过长") String message) {
    }

    @PostMapping("/agent/stream")
    public SseEmitter stream(@Valid @RequestBody AgentRequest req, HttpServletRequest request) {
        UUID userId = currentUserResolver.requireUserId(request);
        conversationService.assertOwned(req.conversationId(), userId);

        SseEmitter emitter = new SseEmitter(180000L);
        Disposable subscription = chatService.streamWithTools(req.conversationId(), req.message())
                .subscribe(
                        chunk -> {
                            try {
                                emitter.send(chunk);
                            } catch (IOException e) {
                                emitter.completeWithError(e);
                            }
                        },
                        emitter::completeWithError,
                        emitter::complete);

        emitter.onCompletion(subscription::dispose);
        emitter.onTimeout(subscription::dispose);
        emitter.onError((e) -> subscription.dispose());
        return emitter;
    }
}
```

## 11. 本轮刻意不做的技术债（别在面试里假装做了）

| 项 | 现状 | 什么时候补 |
| --- | --- | --- |

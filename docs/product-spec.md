# 产品说明书 · AI 学习教练

> 本文件只写**业务与功能**，不写代码、不写表结构。代码怎么落地看 [`mvp-backend-guide.md`](./mvp-backend-guide.md)；
> 数据建模看 [`data-design.md`](./data-design.md)；历史决策看 [`decision-log.md`](./decision-log.md)。

***

## 1. 一句话定位

别人做「让 AI 更懂用户」，这个项目做「**让用户真的学会**」。

**边界声明（写进 README 与面试口径）**：系统能度量的是**回忆表现**（答没答对、第几次对、隔多久），
证明不了内化。主动承认这条边界，比喊「AI 帮你学习」更可信。

***

## 2. 用户与场景

- **第一个用户就是开发者本人**：拿自己正在学的技术资料（官方文档、讲义、自己的笔记）来喂。
- **冷启动不存在**：不靠公共题库，题目从「**你的**材料」出。没有材料就退化成满大街的泛化 AI 问答。
- 典型一天的用法：早上打开看到「3 题到期」→ 讲一段 → 被挑出 2 个漏洞 → 补讲 → 晚上随手问一个报错。

***

## 3. 核心闭环（七步）

```
① 上传资料  → ② 系统读懂并复述一句  → ③ 出任务（提问 / 让你讲 / 引导实践）
      ↑                                            ↓
      └── ⑦ 到点被叫回来 ← ⑥ 记成绩 + 排期 ← ⑤ 补讲 ← ④ 你讲，系统只挑漏洞
```

与旧版（2026-10-15 冻结版）的差别，按 `decision-log.md` 的「版本化修订」处理，不覆盖原记录：

| 项 | 旧版 | 现版 |
| --- | --- | --- |
| 任务形态 | 统一是「回忆题」 | 两类可判分任务：**明确问题** / **讲解任务（费曼）**；引导实践改为独立模式（不判分） |
| 谁发起 | 定时任务到点拉回 | **待办列表**，用户自由选择（不做自动弹窗） |
| 会话与资料 | 会话绑定一份资料 | 资料绑定在**每一道题**上（支持交错混排） |
| 知识点 | 无 | 每道题带 `target`，成绩产生后进入**知识点词汇表** |

***

## 4. 四种会话模式

`t_conversation.mode` 的取值已冻结为四种，不新增。

| 模式 | 用户怎么进入 | 系统干什么 | 记成绩 | 进复习闭环 |
| --- | --- | --- | --- | --- |
| `FREE_CHAT` 自由问答 | 直接在聊天框提问 | 答疑（可挂 RAG 检索自己的资料、可调工具联网） | 否 | 否 |
| `SELF_TEST` 专项突破 | 从「我的资料」选一份，点「考考我」 | 针对这份资料出任务，优先重问该资料下答错过的题 | **是** | **是** |
| `REVIEW` 到期复习 | 从「待办」点到期项 | 到期题 + 从别的资料抽 1 道（交错混排） | **是** | **是** |
| `PRACTICE` 引导实践 | 从「我的资料」点「怎么练」 | 给出可动手做的小项目 / 练习步骤 / 验收标准 | 否 | 否 |

**为什么 `PRACTICE` 不记成绩**：反馈发生在系统外部（编辑器、终端、跑测试），系统看不见结果。
把看不见结果的东西记成成绩就是编数据。`PRACTICE` 的产出是「下一步做什么」，不是分数。

***

## 5. 任务形态：两类可判分任务 + 一类引导

| 类型 | 长相 | 判分口径 | 是否落成绩 |
| --- | --- | --- | --- |
| `FACT` 明确问题 | 「HNSW 的 `m` 参数控制什么？」 | 要点覆盖：答对 / 部分 / 错 | 是 |
| `EXPLAIN` 讲解任务（费曼） | 「假设对方只会 Python、没听过向量检索，把 HNSW 讲给他听」 | **外行听不听得懂**：有没有跳因果、有没有用未定义的术语、有没有只给结论不给理由 | 是 |
| 引导实践（`PRACTICE` 会话） | 「用 pgvector 建一张 1000 行的表，分别用 HNSW 和 IVFFlat 查一次，记录耗时」 | 不判分 | 否 |

**引导实践不是「题型」，是「会话模式」**：它没有作答、没有判分、不进复习闭环（见第 4 节）。
`t_question.kind` 只存 `FACT` / `EXPLAIN` 两个值；引导实践走独立的 `/practice/guide` 入口。

**一次专项突破默认 3 个任务**，其中至少 1 个是 `EXPLAIN`。用户**可以只讲第 1 个就看反馈**，
剩下 2 个仍留在会话里（待办里的「还没测过」会把它带回来，不强制一次讲完，降低单次认知负荷）。

**讲解任务的听众设定由系统给**（外行 / 只会 Python 的后端 / 同专业同学），不给听众的讲解容易变成背课文。

***

## 6. 判分与补讲

| 判定 | 含义 | 排期 |
| --- | --- | --- |
| `PASS` | 要点齐、讲解能被外行听懂 | 按 1 → 3 → 7 天递进 |
| `PARTIAL` | 讲了个大概，但有 1~2 个明确漏洞 | 3 天后重问 |
| `FAIL` | 讲错、或讲不出、或只背结论 | 1 天后重问 |

**补讲**：判 `PARTIAL` / `FAIL` 时，系统返回**漏洞清单**（2~4 条），每条只描述「缺了哪一环」或
「哪一步没说清」，可以给思考方向，但**不给数值、公式、术语定义、结论，也不举例**。
用户可以按漏洞补讲一次。补讲上限 1 次，判完即定，第 3 次提交由服务端直接拒绝（`400`）。

**为什么漏洞清单不能给答案**：给答案等于把补讲的 `PASS` 变成抄写，成绩失真后 1→3→7 的排期全部失效。
完全不会时走 `/help` 求助，那是明码标记「求助过」的通道。

**求助**：讲解中途提问 → **先回答，但该题记「求助过」**（`t_question.help_used = true`），复习时优先重问。
理由：诚实记录，不憋用户。这个行为已冻结，不改。**求助不改变判分**，只影响复习队列的排序。

***

## 7. 待办列表（替代自动弹窗）

不做「打开页面系统自动开口」，不做顶部提示条。所有该做的事进侧栏「待办」，由用户自己点。

| 待办类型 | 出现条件 | 点进去 |
| --- | --- | --- |
| 到期复习 | `t_review_schedule` 有 `PENDING` 且 `due_at <= now()`（一条汇总项，带到期题数） | 建 `REVIEW` 会话 |
| 需要重讲 | 该题最近一次是 `FAIL` / `PARTIAL`、补讲还没做（`attempt_no = 1`），且该题的复习**尚未到期**（到期后归入上一行） | 建 `SELF_TEST` 会话，重问那道题 |
| 还没测过 | **已经出过题**、但还没作答（点进去继续那次测验） | 打开那道测验会话 |

**不列出**「全部资料」列表当待办。待办必须**有限且可清空**，否则会变成永远清不完的任务墙。
**从未出过题的资料也不进待办** —— 资料页上每份材料都有「考考我」按钮，那才是入口。

**交错混排规则**：`REVIEW` 会话 3 个任务 = 2 个到期题 + 1 个来自**其他资料的题**；
若用户只有一份资料、或交错题出不来，则全部用到期题（最多 3 个）。

**清空的边界（个人项目取舍）**：待办在正常使用里靠「答完」清空；MVP **不做**删除资料 / 作废题目的接口。
上传错的材料、或不想做的测验，直接在数据库里跑 SQL 清理（脚本见 `mvp-backend-guide.md` 第 13.4 节）。
所以「还没测过」这一项，在**不答且不手动清理**时会一直留着 —— 这是已知的、被接受的口子。

## 8. 知识点与知识迁移

### 8.1 知识点从哪来

**只从题目来，不从闲聊来。** 每道题在出题时由模型给出 `target`（这道题考的知识点，如「HNSW 的 m 参数」）。

| 状态 | 何时产生 | 能不能用于迁移 |
| --- | --- | --- |
| `CANDIDATE` | 出题写入（还没答过） | **不能** |
| `VERIFIED` | 该题拿到 `PASS` 或 `PARTIAL` | 能 |

**为什么闲聊不抽**：流式输出与结构化抽取不能在一次调用里同时完成，额外发一次请求会让每轮延迟翻倍；
且闲聊里说的「我听说过 RAG」没有经过验证，拿去做类比会教出**错误类比**。

### 8.2 迁移怎么发生

出题时，服务端查该用户最近 5 个 `VERIFIED` 知识点，拼进提示词：

> 用户已掌握：HNSW 的 m 参数、余弦距离、向量维度。
> 如果本次内容与这些有关，请在一个任务里要求用户**用已掌握的概念做类比**。

这是「知识不孤立」的 MVP 真身，成本是一次查询 + 一段提示词。**知识图谱可视化仍不做。**

## 9. 进度可视化（让人有盼头）

只显示**能反映能力的三件事**，不做积分、徽章、排行榜。

| 指标 | 定义 | 为什么选它 |
| --- | --- | --- |
| 已掌握资料数 | 该资料下**所有已出过的题**，最近一次都是 `PASS` 的资料条数 / 总资料条数 | 直接对应「我学会了什么」；不采用「有一题通过就点亮」，那会让进度虚高 |
| 连续学习天数 | 有任一成绩的连续自然日（今天还没答就从未答的那天往前数，不倒扣） | 唯一被验证有效的留存机制（不断签） |
| 待复习数 | `PENDING` 且到期的条数 | 给出「今天要做什么」，可清空 |

**不做**：积分、等级、徽章、排行榜、成就墙。理由：这些指标和「学会」无关，用户集齐徽章也不会讲给你听。

**图表只做一张**：近 8 周每周完成的讲解次数。数据量少时柱子会矮，这是事实，不用假数据撑场面。

## 10. 资料接入

| 方式 | 说明 |
| --- | --- |
| 粘贴文本 | 标题 + 正文 |
| 上传文件 | `.md` / `.txt` / `.pdf`（**PDF 仅限有文字层**；扫描件在入口拒绝） |

**不做网页自动抓取**：官方文档的噪声（导航栏、侧边目录、更新日志）会直接拉低出题质量；
由用户自己下载整理，输入侧由人把关。**这是主动取舍，不是能力缺失。**

**上传后系统做一件事**：读一遍，产出一句 200 字以内的摘要（存在 `t_knowledge_item.summary`），
用于列表展示。**出题用正文，不用摘要**（摘要会丢细节，出题必须基于原文）。
**不在上传时抽知识点**——那时候用户还没学。

***

## 11. 明确的边界（不做清单）

| 不做 | 原因 |
| --- | --- |
| 真遗忘曲线拟合（SM-2 / FSRS） | 没有足够作答数据，拟合出来是自欺欺人。固定 1/3/7 是有意选择 |
| 知识图谱可视化 | 只以「交错混排 + 类比提示」的形式存在，不做图 |
| AI 自主发现「你没想到的问题」 | research 级，12 月前做不出 |
| 语音复述与口述评判 | 要接 ASR/TTS，与最小可用冲突 |
| 扫描件 PDF（OCR） | 需要 Tesseract，不在本轮 |
| 网页抓取导入 | 质量不可控，改为用户自己上传 |
| 积分 / 徽章 / 排行榜 | 与「学会」无关，是虚荣指标 |
| 多用户协作 / 分享 / 团队 | 归属模型只做「一人一份数据」 |
| 删除资料 / 作废题目的接口 | 个人项目，直接用 SQL 清理（`mvp-backend-guide.md` 13.4）；代价是「还没测过」不答就一直在 |
| JWT、限流、部署、监控、CI | 够演示不够上线 |

**容易混淆的两件事**：不做「监控告警 / 部署」，但**做**「模型调用观测」（第 12 节）。
前者是运维基建，后者是产品成本与体验的度量，量级完全不同。

## 12. 观测、上下文与评测（让「好不好」有数字）

### 12.1 观测什么

每次模型调用落一行 `t_ai_call`，记四样东西：

| 记什么 | 怎么读 | 为什么值得记 |
| --- | --- | --- |
| 场景 `scene` | 六类：`CHAT` / `QUIZ_GENERATE` / `GRADE` / `HELP` / `SUMMARY` / `PRACTICE` | 哪一类调用最贵、最慢，一眼看出来 |
| 延迟 `latency_ms` | 按场景取 **P95**，不看平均值 | 平均值会被快的调用拉低，用户感知的是最慢的那几次 |
| 首 token `first_token_ms` | 流式聊天专用 | 用户判断「卡不卡」用的是等第一个字的时间，不是总时长 |
| 用量 `prompt_tokens` / `completion_tokens` | 按场景求和 | 成本就是这两个数，没有它们就只能靠感觉 |

**一条硬规则**：拿不到 usage 就存 `NULL`，并在汇总里单列 `callsWithoutUsage`。
**不用字符数估算 token 来充数** —— 估算值一旦进了表，简历上的数字就变成假数据。

### 12.2 轮数太多怎么办

**按预算裁，不按条数裁。** 现有 `maxMessages(10)` 有两个问题：10 条短消息太早丢上下文；
10 条长代码块又能顶到 2 万 token。改为按字符预算（默认 8000 字符）从最新往前保留，
超预算就丢最旧的；最新一条无论多长都保留（否则会把用户刚说的话裁掉）。

**不做滚动摘要**：把早期对话压成一段 summary 确实更省 token，但每次压缩都要多一次模型调用，
和「降成本」的初衷打架。本轮接受「早期对话被丢掉」，写进技术债。

### 12.3 评测三套

| 评测 | 语料 | 指标 | 为什么这么定 |
| --- | --- | --- | --- |
| 出题 | 10 份跨领域材料 | 3 题结构合格 ≥ 7/10 | 出题是闭环入口，题不合格后面全废 |
| 判分 | 6 条人工标注 × 每条跑 3 次 | 稳定性 ≥ 5/6，与标注一致 ≥ 4/6 | 判分没有客观标准答案，只能测「会不会每次说的不一样」+ 参照一致率 |
| RAG | 5 条查询 + 固定语料 | top5 命中 ≥ 4/5 | 检索链路（embedding → 检索 → 过滤）是否可用 |

数字必须写进 `impl-log.md`，简历只抄那里的数字，**不抄文档里的目标值**。
评测是离线测试类，不进入线上请求路径，也不新增接口。

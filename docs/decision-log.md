## 2026-10-15 · 业务定位（已确认）

**一句话业务定义（用户原话）**

> 别人做的是「让 AI 更懂用户」——烂大街。我做的是「让用户真的学会」。

**推论（修正了此前的层级错误）**

- 系统核心不是「AI 的记忆」，而是「**用户的掌握度**」。
- 记忆（会话、历史）从「产品」降级为「**底座**」：记不住你错哪道题的教练，排不出复习计划。
- 因此此前唯一的记忆实现（Kryo 文件 + 内存 Map）不是要推翻，而是要扶正为底座。

**边界声明（写进 README 与面试口径）**

- 系统能度量的是**回忆表现**（答没答对、第几次答对、间隔多久），**证明不了内化**。
- 主动承认这个边界＝进场优势；只喊「AI 帮你学习」的人说不清自己能证明什么。

## 学习机制 · 四桶归类（2026-10-15 已确认）

| 桶           | 内容                                                           |
| ----------- | ------------------------------------------------------------ |
| 做成功能        | 主动回忆自测、遗忘曲线调度、费曼式复述挑漏洞、交错练习队列                                |
| 当设计原则（不是功能） | 降认知负荷 → 一次只给 3 道题、一屏只放一个任务；好奇心驱动 → 落在 prompt 层：先问用户想搞懂什么，不硬塞 |
| 进 C 类（不做）   | 睡眠 / 运动 —— 聊天 Agent 交付不了，顶多做提醒，成本高、价值低                       |
| 只进叙事        | AI 自主发现「你没想到的问题」—— research 级，12 月前做不出                       |

## 最小闭环（复用已有资产，不重写）

> RAG 存材料 → 出 3 道主动回忆题（不给答案）→ 用户复述 + AI 挑漏洞 → 新表记成绩 → 定时任务按遗忘曲线排复习 → 回到出题（交错练习）

每步的资产映射：

| 步骤     | 复用什么                  | 新增什么                       |
| ------ | --------------------- | -------------------------- |
| 收料     | 现有 RAG / VectorStore  | —                          |
| 出题、挑漏洞 | 现有 ChatClient + 提示词体系 | 出题/评判专用提示词                 |
| 记成绩    | —                     | 新表 test\_record            |
| 排复习    | —                     | 新表 review\_schedule + 定时任务 |

**角色分工（回应「AI 不能保证用户学会」的质疑）**

- 用户侧负责**产出**：写、答、复述 —— 知识只有从你嘴里出来才长在你脑子里。
- AI 侧负责**评判与调度**：挑漏洞、记成绩、排复习。
- AI 不能保证内化；它能保证的是「在该回忆的时候叫你」＋「你没法用假装懂糊过去」。

## 业务交互定义（2026-10-15 定稿冻结）

> 定稿后不再重开。发现偏差走**版本化修订**（在下方补一行说明，不覆盖原记录）。

**三种会话模式**

| 模式     | 触发       | 干什么                                           |
| ------ | -------- | --------------------------------------------- |
| ① 自测会话 | 用户带着材料来  | 从材料出 3 道回忆题 → 用户凭记忆答 → AI 只挑漏洞、**不给答案** → 记成绩 |
| ② 自由问答 | 用户随时提问   | 复用现有 RAG 直接回答（不是测验）                           |
| ③ 复习会话 | 定时任务到点拉回 | 从 `review_schedule` 取题 + **交错混排**另一主题 + 关联提问  |

**「构建知识网络」的 MVP 真身**：交错混排 + 关联提问（例：上次错的复利题 + 本周的通货膨胀 + 「这两者什么关系？」）。知识图谱可视化仍留在 C 类，不夸大。

**用户提问的来源（三个）**

- 对材料的疑问 → RAG 检索 `knowledge_item`
- 对错题 / 成绩的疑问 → `test_record`
- 自由好奇 → 模式 ② 兜底

**已拍板：自测中途用户提问 → 选 A**

- 先回答用户，但该题记为「**求助过**」；复习时优先重问它。
- 理由：诚实记录，不憋用户（用户本人拍板）。
- 否决：B（拒绝回答、逼他先写完）／C（只给线索不给答案）。

**资料接入分层**

| 层       | 内容                        | 时机                    |
| ------- | ------------------------- | --------------------- |
| 第一层     | 用户上传 / 粘贴自己的笔记            | 立即（第一个用户就是他自己，冷启动不存在） |
| 第二层     | AI 搜索 → 给链接候选 → 用户勾选 → 导入 | 排在第一条纵切（记忆落库）之后       |
| Backlog | 其他来源（公众号、播客、视频等）          | 不进 MVP                |

- 第二层**不是新需求**：项目已有 `WebSearchTool`(Tavily) / `WebScrapingTool` / `ResourceDownloadTool` / `FileOperationTool`，属于「串流程 + 加个勾选」，也就是他三分法里的 A 类「多源接入」。
- **没有材料的用户**：MVP 阶段要求必须有材料——「从**你的**材料出题」是这个产品的立身之本，否则退化成满大街的泛化 AI 问答。（可选降级「无材料模式」：仅凭模型知识出题并标注，暂不做。）

**版本化修订 ①（2026-10-16）——练习模式**

- **原判断（不覆盖，留档）**：练习模式进 backlog、MVP 不开发；理由是「没有客观验证器，判分靠不住」
- **修正（用户提出，已采纳）**：AI 只负责「给指引 + 指导」，编译 / 跑测试是外部工具的事，用户自己去做 → **技术上不需要执行器，成本 ≈ 一段引导提示词**
- **修正后的定位**：练习模式**进 MVP**，但它是「模式② 自由问答的引导式入口」，**不产生成绩数据、不进复习闭环**（成绩闭环仍只由自测模式供给）
- **修正后的真代价**：练习模式的反馈发生在**系统外部**（编译器 / 终端），系统看不见结果 → 无法记录成绩。故它不进闭环，也不占用 MVP 主干（主干仍是「主动回忆 + 简化调度」两条）
- **表设计影响**：`mode` 加 `PRACTICE` 一个值（只改 `CHECK`，表结构不动）；`type` 先不加

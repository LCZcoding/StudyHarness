# V2 需求：可批注笔记

> v0.4 · 2026-11-13 · 定稿
> 只写「做什么」和「不做什么」。决策依据、代码考据、验收用例不在本文，开工时看代码。

---

## 1. 一句话

聊天里多一个「生成笔记」开关，AI 直接写成一篇笔记；在笔记里（或已上传的章节正文里）**选中一段文字提问，简短解释出现在正文右侧的批注栏**；还能**在这条解释里再选中陌生词接着问**，新解释缩进挂在它下面。批注和笔记都能改。

---

## 2. 功能需求

### 2.1 生成笔记

- 输入框加第 4 个开关「生成笔记」，默认关，**只管当前这一条消息**。关着就是现在的授人以渔（AI 反问、不给答案）；开着就换笔记提示词，一次性成篇、Markdown、带 `##` 小标题。
- 笔记是**这条会话里的一条消息**，但聊天记录里不铺开全文，只显示一张卡片：`NOTE` 标签 + 标题 + 前 80 字摘要 + 「打开笔记 →」。点开进 `/notes/:id` 全屏页。
- 现有 RAG、工具、SSE、ChatMemory 全部照常，普通问答行为一字不改。

### 2.2 编辑笔记正文

- 笔记页点「编辑」→ 整页变成一个装 Markdown 原文的纯文字输入框 → 改字、加段、删段 → 「保存」变回排版好的样子。不引入富文本/块编辑器。
- 覆盖写，不保留历史版本。

### 2.3 右侧批注栏与追问链（核心）

```
┌─ 正文栏 ───────────────────┐ ┌─ 批注栏 ────────────────────┐
│ ## 二、大致流程             │ │ 批注 1  引用:召回 topK      │
│ 切块→存向量→[召回 topK 片段]│ │ 问:topK 是什么？            │
│   ① 拖选 → 提问 ────────────┼▶│ 答:取[余弦相似度]最高的 K 条…│
│                            │ │        ② 选中这里再问       │
│ 召回的片段拼进提示词…       │ │ [编辑] [删除]               │
│                            │ │         ↓                   │
│                            │ │  子批注 1.1  引用:余弦相似度│
│                            │ │  问:相似度怎么算？           │
│                            │ │  答:向量夹角打分…            │
└────────────────────────────┘ └──────────────────────────────┘
```

**布局**

- 正文一栏、批注一栏，**批注不插进正文里**。按选中文字所在段落分组，组内按创建先后从上往下排；**不做「卡片对齐到正文那一行」**，只用引用原文高亮建立关联。
- 子批注缩进挂在父卡片下方，可一直往下问。链深最多 8 层，UI 缩进到第 3 层后不再右移，只显示层级标签。
- 窗口窄于 1024px 时，批注栏整体移到正文下方。

**提问与生成**

- 在正文里选文字 → 提问 → 生成顶层批注；在**某条批注的答案里选词** → 提问 → 生成子批注。两种走同一个接口，只差一个可选的 `parentId`。
- 解释统一**一段话、60~120 字、不分点**，只讲这个词/这句在当前语境里的意思。非流式。
- 生成子批注时必须把「正文原句 + 上几条解释 + 本次选中的词」一起给 AI，否则会答成脱离上下文的百科解释。
- 批注不写进聊天消息，不新开一轮对话，UI 上不是对话气泡。

**编辑、删除、失效**

- 批注答案可编辑（含子批注），问题和引用快照不可改；改过的答案标「已编辑」。
- 删父批注时连同它的所有追问一起删，前端提示「将同时删除 N 条追问」。
- 笔记正文改过之后，批注按「段落 → 引用原文全文搜索」重新归位；找不到就把批注放进「原文已修改」分组，**问答内容保留，只是不再精确贴着**。子批注同理，只是拿引用词去父批注答案里找。宁可降级，不做锚点维护系统。

**边界**

- 批注归属必须校验到当前用户；`parentId` 必须存在、属于本人、且与当前目标一致，否则拒绝（防越权）。
- 限额：引用 ≤300 字、问题 ≤500 字、单个目标批注总数（含子批注）≤200、链深 ≤8。

### 2.4 阅读页复用

- 已有章节阅读页换成同一个组件，唯一差别是 `:bodyEditable="false"`：**正文只读**（那是用户上传的原始资料），不显示编辑按钮。
- **批注功能完全一样**：选段提问、右栏批注、批注里追问、编辑/删除批注全部可用。
- 现有「我读完了，开始检测」和翻页不动。

## 3. 落地清单

**数据**：只新增一张 `t_annotation` —— `user_id / target_type / target_id / parent_id(自引用,可空) / block_key / quote / question / answer / edited / created_at`。另有一处 `t_message.type` 的 CHECK 放宽到含 `NOTE`。交付为独立迁移文件 `db/migration-v2.sql`，不改原 `schema.sql`。

**接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/ai/chat/stream` | 现有接口，`StreamRequest` 加 `asNote`；SSE 多一帧 `note` |
| GET / PUT | `/notes/{id}` | 读 / 保存笔记正文 |
| GET | `/annotations` | 按段落分组、按 `parentId` 组树 |
| POST | `/annotations/ask` | 生成批注，`parentId` 可选 |
| PATCH / DELETE | `/annotations/{id}` | 改答案 / 删除（含级联） |

**代码**：前端新增 `AnnotatableDoc.vue`（两栏 + 编辑/预览）、`AnnotationCard.vue`（递归卡片）、`NoteDetailView.vue`；改 `GuideChatView.vue`（开关 + 笔记卡片）、`SectionReadView.vue`（接入组件）、`chatStream.js`、`router`。后端新增 `NoteService`、`AnnotationService` 及对应两个 Controller；`ChatService` 与 `LoveApp` 各加一处分支。**其余 Service 一行不动**，所有 AI 调用走现有服务端默认模型。

## 4. 实施顺序（两个可独立停、独立演示的切片）

1. **批注内核**：迁移文件 + 接口 + 两个组件 → 先接阅读页。
   验收：选一句提问，右栏出现短解释；在解释里再选词追问，生成缩进的子批注；刷新后层级还在；换账号看不到。
2. **笔记生成**：`asNote` 开关 → 笔记提示词 → NOTE 卡片 → 笔记详情页与编辑 → 挂上同一个组件。
   验收：同一会话先普通问一句、再开开关生成笔记，两者互不干扰；笔记可编辑；编辑后旧批注仍可读。

## 5. 明确不做

- ❌ 用户级 API Key 配置：设置页、浏览器存 key、`X-AI-Key`、动态 ChatModel、前端直连模型厂商，全部不做。沿用现有 `application-local.yml`。
- ❌ 全局浮动 AI 助手、跨页面上下文保持；只做笔记页和阅读页两处。
- ❌ 会话级模式切换、把一问一答全改成笔记模式。
- ❌ 富文本 / 块编辑器（Tiptap、Editor.js）、拖拽、工具栏。
- ❌ 字符级精确锚点、编辑后自动精确重定位、批注卡片与正文行的像素级对齐 / 滚动同步。
- ❌ 修改批注的问题与引用快照、批注版本历史、跨批注引用与合并、卡片上做输入框式多轮对话。
- ❌ 独立 `t_note` 表、「我的笔记」列表页、双向链接、来源锚点、回收站、标签/搜索、分享导出协作（PAI 文档那一整套）。
- ❌ 学习画像、掌握度、复习队列的改造；移动端专门适配（仅做窄屏右栏下移）。
- ❌ 批注解释走「授人以渔」引导式人格 —— 默认直给且简短。

## 1. 背景与定位

现状：聊天是「授人以渔」——AI 反问、不给答案；资料上传后在章节阅读页只能读、读完做检测。用户在阅读中碰到陌生概念，只能另开一轮对话，解释和原文分离、留不下来。

本功能让**解释长在原文旁边**。

一句话：聊天输入框多一个「生成笔记」开关，AI 直接写成一篇笔记；在笔记里（或已上传的章节正文里）选中一段文字提问，简短解释出现在**正文右侧的批注栏**；还能在这条解释里再选中陌生词接着问，新解释缩进挂在它下面。笔记和批注都能改。

范围边界：只覆盖「笔记详情页」与「章节阅读页」两个界面；现有问答、出题、判分、复习链路行为不变。

## 2. 术语（用户视角）

| 词 | 意思 |
|---|---|
| 正文 | 屏幕上中间那一栏的 Markdown 内容，可能是 AI 写的笔记，也可能是你上传的章节 |
| 笔记 | AI 一次写成的一整篇稿子，有标题和 `##` 小标题 |
| 笔记卡片 | 笔记在聊天记录里的折叠入口，不铺开全文 |
| 批注 | 选中一句话提问后，右侧出现的一张小卡片：引用了哪句、问了什么、AI 怎么答 |
| 子批注（追问） | 在**某条批注的答案里**再选中一个词提问，新问题挂在那条批注下面、缩进一层 |
| 引用快照 | 批注上抄下来的「当时选的是哪句话」，不可修改，用来在正文改动后重新找位置 |
| 批注栏 | 正文右侧独立的一栏，批注按段落分组、按先后往下排 |
| 「原文已修改」 | 正文改到连引用快照都找不着时，批注挪到这里：问答内容还在，只是不再贴着某段 |

## 4. 功能需求

### 4.1 生成笔记

**FR-01 · 消息级开关**
输入框增加第 4 个开关「生成笔记」，默认关，**只作用于当前这一条消息**（发送后自动复位）。关着时行为与改动前完全一致（引导式、可用 RAG / 工具 / 做成题）；开着时改用笔记提示词，且不挂 RAG 与工具。不得改成会话级模式切换，不得把一问一答整体换成笔记模式。

**FR-02 · 成篇输出**
开启后 AI 一次性写成一篇 Markdown 笔记：结论前置，`##` 分 2~4 节，覆盖「是什么 / 为什么需要 / 大致流程或关键参数 / 常见误区」，1000~2000 字；不反问、不引导、不留「你试试」这类话；不确定处明写不确定，不伪造链接与版本号。

**FR-03 · 会话内不刷屏**
笔记仍是该会话里的一条消息，但聊天记录里只显示一张卡片：`NOTE` 标签 + 标题 + 前 80 字摘要 + 「打开笔记 →」。刷新历史后仍能认出哪些是笔记卡片。

**FR-04 · 笔记详情页**
点卡片进入全屏页，展示整篇笔记；此处承载正文编辑与批注。

### 4.2 编辑正文

**FR-05 · 纯文本编辑**
笔记页点「编辑」→ 整页变成一个装 Markdown 原文的纯文字输入框 → 改字、加段、删段 → 点「保存」变回排版好的样子。覆盖写，不保留历史版本。不提供富文本工具栏、拖拽、块编辑。

### 4.3 右侧批注栏与追问链（核心）

```
┌─ 正文栏 ───────────────────┐ ┌─ 批注栏 ────────────────────┐
│ ## 二、大致流程             │ │ 批注 1  引用:召回 topK      │
│ 切块→存向量→[召回 topK 片段]│ │ 问:topK 是什么？            │
│   ① 拖选 → 提问 ────────────┼▶│ 答:取[余弦相似度]最高的 K 条…│
│                            │ │        ② 选中这里再问       │
│ 召回的片段拼进提示词…       │ │ [编辑] [删除]               │
│                            │ │         ↓                   │
│                            │ │  子批注 1.1  引用:余弦相似度│
│                            │ │  问:相似度怎么算？           │
│                            │ │  答:向量夹角打分…            │
└────────────────────────────┘ └──────────────────────────────┘
```

**FR-06 · 布局**
正文一栏、批注一栏，批注**不插进正文**。按「选中文字所在段落」分组，组内按创建先后从上往下排；**不做卡片与正文行的像素级对齐**，只用引用高亮建立关联。窗口窄于 1024px 时，批注栏整体移到正文下方，不得出现横向滚动。

**FR-07 · 顶层批注**
在正文里选中一段文字 → 就地提问 → 右侧出现卡片。批注不写进聊天消息、不新开一轮对话、不是对话气泡。解释统一**一段话、60~120 字、不分点、不列清单、不加标题**，只讲这个词/这句在当前语境里的意思；非流式。生成时必须携带全文语境（当前段落 + 全文片段），不得脱离语境答成百科词条。

**FR-08 · 子批注链**
在**某条批注的答案里**选中一个词 → 提问 → 新卡片挂在该批注下面。生成时必须携带「正文原句 + 上几条解释 + 本次选中的词」作为上下文。链深最多 8 层。追问默认折叠成一条「展开 N 条追问」小横条，手动点开后子卡片**独立平铺**、不缩进、不套在父卡片里，层级靠「第 N 层」标签表达。顶层与子批注走同一个操作，差别仅是「有没有上一条」。

**FR-09 · 编辑与删除**
批注答案可编辑（含子批注），改过标「已编辑」；问题与引用快照不可改。删除父批注时连同它下面所有追问一起删，删除前必须提示「将同时删除 N 条追问」。

**FR-10 · 正文改动后的降级**
笔记正文被编辑后，批注按「原段落 → 引用快照在全文搜索」重新归位；找不到就放进「原文已修改」分组，**问题与答案原样保留**，只是不再精确贴着。子批注同理，改的是「在父批注答案里找引用词」。宁可丢「贴得准」，不得丢内容；不得为此引入锚点维护系统。

### 4.4 复用与规则

**FR-11 · 阅读页复用**
章节阅读页换成同一套组件，唯一差别是**正文只读**（那是用户上传的原始资料，不显示编辑按钮）。选段提问、右栏批注、批注里追问、编辑/删除批注全部可用。原有「我读完了，开始检测」与翻页不动。

**FR-12 · 归属**
笔记、批注、章节的读/改/删都必须校验属于当前登录用户。`parentId` 必须存在、属于本人、且与当前目标一致，否则拒绝。未登录一律拒绝。

**FR-13 · 边界与限额**
引用 ≤300 字、问题 ≤500 字、单个目标批注总数（含子批注）≤200、链深 ≤8、答案 ≤2000 字。跨段落选区忽略并提示「请只选一段内的文字」。超限时不得发起模型调用。

### 4.5 笔记列表（2026-11-15 新增）

**FR-14 · 集中入口**
左侧导航新增「笔记」入口（排在「资料库」之后），列出当前登录用户的**全部**笔记，按最近更新倒序。每条显示：标题（取正文第一个标题，与聊天卡片、详情页顶栏同源）、前 80 字摘要、字数、批注数、更新时间；点击进入该笔记详情页。没有笔记时显示空态并说明「在对话里打开『生成笔记』开关，AI 会直接写成一篇」。

- 只列自己的笔记；归属口径与 `FR-12` 相同，不得出现别人的。
- **不做**：搜索、筛选、排序切换、标签、收藏、删除、分页（首屏最多 50 条，不做游标）。
- 列表项文案由前端复用与聊天卡片同一份实现，**后端只返回正文原文与元数据**，不重复实现标题 / 摘要提取。

### 4.6 非功能需求

| ID | 要求 |
|---|---|
| NFR-01 | 所有新增模型调用纳入现有 `t_ai_call` 观测，可区分笔记生成 / 顶层批注 / 子批注 |
| NFR-02 | 前后端均不引入新依赖；不新建模型 bean、不新增任何 API Key 存取路径 |
| NFR-03 | 正文经 Markdown 消毒渲染；批注文本不得作为 HTML 插入；参数化查询，无字符串拼接 SQL |
| NFR-04 | 数据库改动以独立迁移脚本交付，可回滚，且改动的约束必须与代码同步 |

## 5. 明确不做（Non-goals）

1. ❌ 用户级 API Key 配置：设置页、浏览器存 key、请求头带 key、动态模型、前端直连模型厂商。沿用现有服务端默认配置。
2. ❌ 全局浮动 AI 助手、跨页面上下文保持；只做笔记页与阅读页两处。
3. ❌ 会话级模式切换、把一问一答整体改成笔记模式。
4. ❌ 富文本 / 块编辑器（Tiptap、Editor.js）、拖拽、工具栏。
5. ❌ 字符级精确锚点、编辑后自动精确重定位、批注卡片与正文行的像素级对齐 / 滚动同步。
6. ❌ 修改批注的问题与引用快照、批注版本历史、跨批注引用与合并、卡片上做输入框式多轮对话。
7. ❌ 独立笔记表、双向链接、来源锚点、回收站、标签/搜索、分享导出协作、笔记删除。
   （原「我的笔记列表页」已于 2026-11-15 移出 Non-goals，改为 `FR-14`：只做「列出自己的笔记并点开」，不做其上叠的检索与整理能力。）
8. ❌ 学习画像、掌握度、复习队列改造；移动端专门适配（仅做窄屏右栏下移）。
9. ❌ 批注解释走「授人以渔」引导式人格 —— 默认直给且简短。

## 7. 假设与依赖

- 用户已登录，沿用现有 Session 体系；本版不做账号体系改动。
- 服务端默认模型可用，密钥沿用 `application-local.yml`。
- 迁移脚本已在目标库手工执行（无 Flyway/Liquibase）。
- 单人开发，无评审流程；发现设计与代码不符时以「先改文档再改代码」为准。
